# Screen views

The decider judges an option best when it sits inside a screen they already know: real header, real density, real data. On a blank page every option looks fine.

This is the opposite of a `prototype`. A prototype's variants disagree about everything. Here the question fixes what varies, so every option is **the same screen with one region swapped**. Mark that region (a dashed outline works) so the eye goes straight to it, and name the mark in the sentence above the view.

## The screen exists (preferred)

Find the screen in the source from the route or component the user named. Copy its colors, type, spacing and components, so each option looks like the product. Change only the region the question is about.

## The screen doesn't exist yet

If it would naturally live inside an existing screen (a new section on a profile page, a new step in a flow), it still counts as existing: mount it in that screen.

Otherwise build it from the product's own colors, type, spacing and components. When there's no product to borrow from, invent a plain look and keep the layout realistic.

If the look is invented, say so on the Start here tab, so nobody mistakes it for the shipped design.
